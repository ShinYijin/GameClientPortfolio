1스킬 데이터 구조 정규화 — 데이터 주도 전투 구조 확립2024.10 ~ 2025.01 · 설계·구현 주도▶
문제

발동 조건, 쿨타임, 자원, 판정, 실행 효과가 Skill 테이블 한 곳에 결합돼 있었습니다. 캐릭터별 발동 규칙이 늘 때마다 코드 분기가 추가됐고, 같은 판정이나 효과를 다른 스킬에서 재사용할 수 없었습니다.

역할

스키마 설계부터 참조 코드 마이그레이션, 스킬 편집 툴 대응까지 전 과정을 맡았습니다.

해결
  • 레거시 스킬 활성화 시스템을 제거하고 상황 기반 활성화 구조로 전환했습니다.
  • 테이블을 역할별로 분리했습니다: 발동 조건, 스킬-판정 연결, 판정 형상, 실행 효과(N:M 그룹).
  • 발동 검증 파이프라인을 정비해 자원·쿨타임 소모 시점을 정의하고, 클라이언트 선검증으로 불필요한 패킷 왕복을 없앴습니다(이후 구조 변경으로 지금은 클라이언트 검증이 발동 판정 자체입니다).
  • 스킬 성장 구조를 1차(강화)에서 2차(레벨·레벨별 효과 치환)로 개편하고, 쿨타임을 개인/스탯/파티 공유 3중 구조로 정리했습니다.
결과

신규 캐릭터 스킬을 코드 수정 없이 테이블 조합만으로 추가하는 구조가 자리 잡았습니다. 판정 테이블의 참조 방향은 실데이터로 검증한 뒤 역전하기로 결정하는 등, 설계→적용→회고 사이클을 직접 운영했습니다.

2콤보 시스템 재설계2024.11 ~ 2025.06 · 설계·2회 개편▶
문제

연타·차지·저스트·캔슬 파생이 늘면서 체인 타입이 19종까지 증가했고, 타입 간 조합 규칙이 코드 곳곳에 흩어져 새 콤보를 추가할 때마다 기존 콤보가 깨질 위험이 있었습니다.

역할

재설계안 작성, 구현, 캔슬 규칙 개편을 주도했습니다.

해결
  • 체인 타입 매트릭스를 부모 체인 트리 + 서로 독립적인 속성 4개(캔슬 가능 여부, 보장 시간, 입력 이벤트, 조건)로 분해했습니다.
  • 캔슬 규칙을 4단계로 발전시켰습니다: 보장 시간 → 행동 차단 보장 → 스킬 등급 규칙 → 캔슬 가능 일괄 규칙.
  • 선입력 예약, 연타 인식용 입력 타입, 입력 시간 기반 체인을 추가했습니다.
  • 클라이언트-서버 체인 진행 정책을 정했습니다: 플레이어 스킬은 클라이언트 주도, 몬스터는 내장 서버 주도. 이후 내장 서버의 스킬 처리가 분리되면서 지금은 모든 유닛의 체인이 클라이언트 한 곳에서 진행됩니다.
결과

신규 캐릭터 3종의 차지·연타 콤보를 데이터 작성만으로 조립했습니다. 체인 캔슬 시 판정 정지 누락, 예약 인덱스 오류 같은 프레임 단위 타이밍 버그를 재현하고 수정했습니다.

문제

파티원의 전투 기여를 게이지로 모아 발동하는 협동 필살기를 새로 만들어야 했습니다. 기여도 산정, 발동 조건, 보스 상태 변화, 멀티플레이 동기화, UI가 모두 얽힌 수직 통합 시스템입니다.

역할

시스템 발제 단계부터 라이브 QA까지 주 담당으로 맡고 있습니다.

해결
  • 기여도 산정: 군중 제어·브레이크·저스트·원소 융합 등 기여 이벤트를 테이블 기반으로 점수화하고, 등급(C/B/A/S)과 감쇠를 계산해 데미지 배율에 연동했습니다. 소환수 기여는 소환자에게 귀속했습니다.
  • 보스 상태 전이: 브레이크 ↔ 리미트 브레이크 전이 규칙과 회복 예외 처리, 전용 연출을 구현했습니다.
  • 멀티플레이 동기화: 게이지 스냅샷 전파와 준비 유저 관리를 구현하고, 유저 이탈·호스트 이송 시 던전 기믹 정보를 넘기는 전용 패킷을 새로 만들었습니다.
  • UI(버튼·게이지·토스트), 시네마틱 중 입력 차단, 궁극기와의 배타 처리를 구현했습니다.
결과

라이브 QA 이슈 20건 이상을 해결했습니다.

4전투 이벤트 기록 통합 + 퀘스트 전투 조건 집계2026.09 · 조사·설계·구현▶
문제

기획팀이 전투 행동 기반 퀘스트 조건 7종을 요청했습니다. 그런데 기존 전투 기록 시스템 6종이 같은 이벤트를 발신 지점마다 따로 기록하고 있어, 집계기를 그대로 얹으면 기록 불일치가 더 늘어날 상황이었습니다.

역할

요구사항 범위 조사부터 설계, 구현까지 맡았습니다.

해결
  • 퀘스트 구조, 서버 검증 규칙, 프로토콜을 3개 층으로 나눠 조사해 "서버와 프로토콜은 완비, 클라이언트 집계기만 없음"으로 범위를 특정했습니다. 서버 검증 계약(값 클램프, 중복 제거, 조건 위반 시 패킷 전체 거부)을 클라이언트 데이터 구조에 반영했습니다.
  • 기록 시스템 6종의 사용처를 전수 조사한 뒤 정적 디스패처를 만들어 발신 지점 11곳을 1줄 호출로 교체하고, 귀속 규칙(소환수→소환자, 부위→본체)을 한 곳으로 모았습니다.
  • 던전 단위 집계 구조체를 만들고 보상 패킷 기입 경로를 하나로 합쳤습니다. 죽은 코드 6묶음도 정리했습니다.
결과

조사부터 빌드 통과 커밋까지 4일(27개 파일). 조사 과정에서 보상 패킷의 사망·처치 수 오전송으로 생존·사냥 퀘스트 2종이 영구 미진행이던 버그와 원소 융합 기록 누락을 함께 찾아 수정했습니다.

53인 파티 교체 · 지원 스킬 · 변신2024.09 ~ 현재 · 구현·리뉴얼▶
문제

교체 중 피격이나 사망이 겹치면 상태 머신이 꼬여 교체가 멈추거나 유닛이 남는 라이브 이슈가 반복됐고, 대기 캐릭터가 난입해 공격하는 지원 스킬도 추가해야 했습니다.

해결
  • 교체 상태를 상태 머신에서 플래그 기반으로 리팩토링하고 검증 실패 지점마다 즉시 해제해 상태 경합을 없앴습니다.
  • 등장 위치 5단계 보정(내비게이션 체크 포함), 락온 승계, 퇴장 유닛의 버프·타겟·판정 정리를 구현했습니다.
  • 지원 스킬은 기존 교체 파이프라인을 재사용해 중복 구현 없이 만들고, 교체·지원·저스트 교체가 하나의 파티 공유 쿨타임을 쓰게 했습니다.
  • 상황 조건 7종을 평가하는 스킬 활성화 구조와 몬스터 AI 스킬 선택(조건 우선 → 가중 룰렛)을 구현했습니다.
  • 변신 캐릭터의 변신·해제 흐름(버프 → 페이즈 변경 → 유닛 교체)을 구현하고, 변신의 수명을 버프에 맡겨 버프가 끝나는 경로라면 어디서든 같은 해제가 일어나게 했습니다.
결과

교체 중 충돌 통과, 교체 후 모델 잔존, 변신 미해제 등 라이브 이슈를 해결하고, 교체 예정·사망 유닛의 조건 오발동 엣지 케이스를 차단했습니다.

6전투 카메라2025.08 ~ 현재 · 구현·튜닝▶
문제

액션 전투에서는 연출 일관성과 상황별 보정이 충돌합니다. 다단 히트 중 타겟 사망, 보스의 지면 잠입, 교체 직후 시점처럼 카메라가 튀거나 방향을 잃는 사례가 계속 나왔습니다.

해결
  • 락온: 타겟 선정·해제 규칙, 타겟 예외 태그, 소켓 기반 락온 UI, 공격 중 락온 허용으로 조작 정책 개선.
  • 화면 내 프레이밍 박스 기반 추적 카메라 도입, 저속 보정 시 떨림 방지 가드.
  • 타격·스킬 시 방향 자동 보정과 플랫폼별(모바일 터치/패드/PC) 정책 분기.
  • 사망 타겟 즉시 해제, 지면 잠입 추적용 타겟 상대 높이 커브, 교체 시 일직선 정렬 옵션.
  • (2026.10, 개인 브랜치·반영 대기) 카메라 보간의 프레임 독립화: 프레임율에 따라 같은 시각의 카메라 위치가 달라지던 보간을 지수 감쇠로 바꾸고, 기준 FPS 속도 환산을 붙여 기획이 맞춰 둔 값의 체감을 유지했습니다.
  • (2026.10) 게임패드 카메라 반전·가속, 카메라 거리 단계 옵션 추가. 거리 배율은 평소 카메라에만 적용해 연출 카메라에는 영향이 없게 했습니다.
  • (2026.10) 연출 중 카메라 입력 차단 키 161개 중 152개가 마우스·패드 축만 막아 모바일 터치 회전이 열려 있던 문제를, 다른 화면의 입력 정책을 깨지 않는 범위로 수정했습니다.
  • (2026.10) 자체 제작한 카메라 시뮬레이터(7번 항목)로 찾은 버그 6건 수정: 프레이밍 카메라의 회전 누적, 사망 유닛이 카메라 대상에 남는 문제, 빈 설정 키가 기존 카메라 설정을 지우는 문제 등.

보정 기준 각도와 커브를 설정값으로 노출해 기획팀이 코드 수정 없이 튜닝할 수 있게 했습니다(실제로 기준 각도는 기획팀이 설정값만으로 조정해 운영 중). 보간 전환은 시뮬레이터에서 전 연출을 60fps로 돌려 교체 전과 위치 차이 0을 확인했고, 저프레임 편차는 최대 120cm에서 77cm로 줄었습니다.

7AI 코딩 에이전트 활용 — 기획·개발 지원 도구 제작2026.09 ~ 현재 · 1인 제작▶
문제

전투 데이터는 엑셀 20개 파일·50여 시트에 흩어져 있고 설명 시트는 코드와 어긋나 있었습니다. 카메라 연출은 에디터에서 직접 재생해야만 확인할 수 있었습니다. 본업 일정 안에는 도구를 만들 시간이 없었습니다.

역할

AI 코딩 에이전트(Claude Code)에게 구현을 맡기고, 요구 정의·설계 결정·기각 판단·코드 근거 검증을 맡았습니다.

해결
  • 작업 규칙 설계: "값과 규칙의 기준은 기획 문서가 아니라 C++ 구현", "C++를 같은 순서·조건으로 옮기고 임의로 개선하지 말 것", "코드로 확인한 내용만 싣기" — AI의 그럴듯한 추측을 막는 규칙을 먼저 세웠습니다.
  • 검증의 기계화: 화면을 볼 수 없는 에이전트를 위해 헤드리스 브라우저 DOM 덤프·스크린샷·클릭 하네스를 만들고, 전수 순회(퀘스트 화면 1,864개, 카메라 시뮬레이션 1,323회)로 결과를 확인했습니다.
  • 스킬 데이터 뷰어/작성 도구: 테이블 52개·4.7만 행을 참조 트리로 연결하고, 작성 가이드 7종, 엑셀 붙여넣기 행 생성, 노드 캔버스 조립, 스킬 타임라인, 이동 경로 미리보기(게임 계산식 이식), 데이터 점검을 제공합니다(약 1.1만 줄).
  • 카메라 연출 시뮬레이터: 연출 카메라 키·카메라 설정 에셋·카메라 경로를 프레임 단위로 재현합니다. 에셋 파일을 에디터 없이 직접 파싱하고 연출 434개를 전수 시뮬레이션합니다(약 6,700줄).
  • 던전·퀘스트 뷰어(진행 흐름·스폰 맵·퀘스트 체인·코드 근거가 붙은 데이터 점검), 전투 기획서 작성 도구(기획서 → 테이블 행 생성). 스킬 통합 타임라인·맵 로드 없는 모의 전투 에디터 툴 2종은 제작 중입니다.
결과

설명 시트와 코드가 다른 항목 11건을 대조표로 정리했고, 데이터 점검으로 "코드가 경고 없이 건너뛰는" 오기입 369건 등 실제 오류를 분류했습니다. 카메라 시뮬레이터 재현 과정에서 C++ 버그 6건과 입력 차단 누락을 찾아 실데이터 영향 통계와 함께 수정했습니다(6번 항목). 결정·기각 사유·검증 방법을 기록으로 남겨 같은 방식을 도구마다 반복 적용했습니다.
